# 0040 — Widget の中身は共有の文書で、キー単位で合流する

## 背景

[0039](0039-widgets-are-shared-components-with-an-origin-and-boards-are-placements.md) でボードと Widget は共有になったが、Widget が自分で持つ中身には置き場がなかった。唯一の例である生成アプリ（[0024](0024-generated-apps-live-in-object-widgets.md)）は `widget_apps` / `widget_app_data` に所有者ごとに保存し、共有ボードの上では作成者だけの Widget（出自 `me`）として置いていた。ほかの人には中身のない枠が見えるだけで、同じアプリを一緒に使えない。

今後、HTML を出力するスキルの Widget や表計算の Widget も、中身を自分で持つ。

決定の時点で `widget_apps` は 0 行だった。

## 選択肢

中身の同期:

1. **行ごと上書きし、revision の不一致で拒否する**（0024 の方式を共有に広げる）。
2. **トップレベルのキー単位で合流する** — 変えたキーだけを送り、サーバーが1文で合流する。
3. **順序付きの操作ログとスナップショット**（Fluid Framework の方式）。

下書き（採用前のプレビュー）:

- a. 共有の中身に含める。
- b. 本人だけの置き場に持つ。

## 決定

2 と b。

### 置き場

| テーブル | 持つもの | 見られる人 ＝ 編集できる人 |
|---|---|---|
| `widget_documents`（`widget_id`, `part`） | Widget の中身。パートごとに JSON オブジェクト1つ | その Widget を見られる人 |
| `widget_viewer_state`（`widget_id`, `user_id`） | 本人だけの状態 | 本人（かつ Widget を見られること） |

どちらも Widget の削除で連鎖して消える。Widget を最後のボードから外すと Widget が消えるので、中身も全員から消える。定義が `holdsContents` の Widget は、外す前に確認を出す。

### 合流

`merge_widget_document(widget, part, set, unset)` が `value = (value - unset) || set` を1文で行う。別々のキーを同時に保存した2人は両方残り、同じキーは後が勝つ。クライアントは保存前の状態との差分（`statePatch`）だけを送る。

`widget_documents` を `supabase_realtime` に入れ、既存の `deltaStream` がクエリを無効化する。

### 生成アプリ

- パート `app` に採用中のアプリと1つ前の版、パート `data` に入力。どちらも Widget を見られる全員が共有する。
- 下書きと依頼文は `widget_viewer_state`。「Use this app」で `app` に書き、全員のアプリが置き換わる。
- 枠の中のアプリは `alcon.save(next)` で状態全体を渡す。ホストは、そのアプリが最後に受け取った状態との差分だけを送り、合流後の状態をアプリに返す。ほかの人が保存したときは新しい状態を渡し、アプリは `alcon.onChange(fn)` で受け取る。
- 生成アプリを作成者だけのものにする `personal` の定義はなくした。Widget は生まれたボードの対象を出自にする。
- `widget_apps` / `widget_app_data` は削除した。

## 根拠

**上書き＋拒否にしない理由。** 2人が同じアプリの別の欄を触るたびに、片方が「再読み込みしてやり直し」になる。共有するほど使えなくなる。

**操作ログにしない理由。** 今ある中身はフォームやチェックリストの入力で、キーが独立している。キー単位の合流で衝突の大半が消え、順序付け・再生・スナップショット・圧縮を持たずに済む。操作ログが要るのは、操作が可換でなく順序が結果を決める中身（表計算のコマンド、文字単位の文章）で、そのときに同じ `widget_documents` をスナップショットの置き場として足せる。

**下書きを本人だけにする理由。** 生成の途中経過が全員のアプリを置き換えると、誰かの試行が全員の作業を止める。採用を明示の操作にする。

**作成者専用をやめる理由。** 共有ボードの上の専用 Widget は、ほかの人には用途の分からない枠でしかなかった。出自がボードの対象になるので、見えない枠は別のボードに置いたときにしか生じない。

**外すと中身が消える、を受け入れる理由。** 0039 の「どのボードにも置かれていない Widget は消す」をそのまま適用する。残すなら、置かれていない Widget を探して戻す画面が要る。確認を挟むことで事故を防ぐ。

## 覆す条件

- 同じキーの同時編集で入力が失われる報告が出る（1つの配列に全レコードを入れるアプリなど）— 生成の指示で分割を促しても足りなければ、キーの中まで合流するか操作ログに移る。
- 順序が結果を決める中身を持つ Widget を作る（表計算）— 操作ログとスナップショットを別 ADR で決める。
- 外した Widget を戻したい要求が出る — 削除をやめ、置かれていない Widget の一覧と復元を作る。
- 下書きを複数人で見たい要求が出る — 下書きを共有のパートに移し、誰の下書きかを持たせる。
