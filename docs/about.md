# Alcon とは

Alcon は、組織の仕事を人と AI が一緒に進める運用基盤を目指します。チームの誰かに仕事を頼むのと同じように、Alcon の AI にやるべきことを伝えるだけで、AI が計画を立て、必要な作業を進めます。

## 特長と仕組み

Alcon は、特別な使い方を覚えなくても使える道具を目指します。問い合わせの整理、調査、報告書の作成といった日々の仕事に対応し、組織の大きな目標にも取り組みます。

- **目標から計画へ**：達成したいこと（Strategy）と、何をもって達成とするか（成功条件）を伝えると、AI が会話で足りない前提を確かめ、仕事を持ち場（Object）と行動（Element）に分けた計画を作ります。計画は人が確かめてから実行に移します。
- **人と AI の分担**：調査・下書き・集計・分析は AI に、判断・承認・対外的な約束は人に割り当てます。誰に任せるかの決まりを書いておけば、そのとおりに担当者を決めます。
- **自律的な実行**：AI は Web で調べ、表に記録し、文書を作ります。登録したマシンでは、ブラウザを開いてフォームに入力するといった操作も行います。
- **アプリを閉じても続く仕事**：決まった時刻や外部からの知らせ（Webhook）をきっかけに、仕事を自動で始めます。始めた人の権限で動き、途中で止まっても続きから再開します。
- **人の判断が要るときだけ呼ぶ**：外部への送信や書き込みなど承認が要る操作と、AI では決められない判断は、「判断待ち」として人に回します。仕事の流れをボードで一覧にし、人が判断と評価に集中できるようにします。
- **組織の記録として残す**：目的・成功条件・前提・意思決定、集めたデータ（Table）、文書（Note・ファイル）を、すべて組織の記録として残します。次の仕事を始める AI は、この記録を読んで進めます。
- **仕事のやり方を定義する**：仕事の進め方・止める条件・成果物の形・使う連携を「ハーネス」として書いておくと、AI はそれに従います。ハーネスは保存した時点で検査し、問い合わせ対応・クレーム分析・営業のフォローなど、すぐ使えるものを用意します。

## 連携できるサービス

Alcon は、組織がすでに使っているサービスとつながり、その中の仕事を AI が進められる基盤を目指します。コネクタは、Alcon の AI が組織のさまざまな仕事を進めるための土台です。

- **GitHub**、**Google Drive** と OAuth で接続します
- **Linear**、**Asana**、**Slack** と接続します
- MCP サーバーや任意の REST API と、URL と認証情報を登録して接続します

AI のモデルは、標準の Claude に加えて DeepSeek や Kimi などに切り替えられるようにします。

Gmail と、日本の組織が日常的に使うサービスとの連携を広げていきます。

## 安全性と管理

Alcon は、組織が安心して仕事を AI に任せられる基盤を目指します。

- **組織ごとに分かれたデータ**：データを Space（組織）ごとに分け、見られる範囲をデータベースの権限（RLS）で決めます。AI も、仕事を始めた人が見られる範囲でしか読み書きしません。
- **AI に見せない認証情報**：連携サービスの認証情報を暗号化して保管し、AI の文脈にも道具の引数にも出しません。登録した送信先へのリクエストにだけ差し込みます。
- **送信先の制限**：外部への通信を https だけに限り、社内ネットワークやローカルのアドレスには送りません。登録した URL の外にも出ません。
- **重要な操作の前に確認**：書き込みや送信の前に、人の承認を求めます。承認を、実行する内容そのものに結び付け、承認した内容と違う操作は実行しません。
- **履歴の確認**：AI が行った操作、承認を待っている操作、自動で始まった仕事の記録を、Element ごとの実行記録とアクティビティで確かめられるようにします。
- **主導権は利用者に**：接続するサービスと、操作ごとに毎回確認するか任せるかを、組織が選べるようにします。権限の変更や接続の解除はいつでもできます。AI の費用には Space ごとと実行ごとの上限を設け、上限に達すると止めます。
