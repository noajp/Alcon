# 0033 — The REST API is the MCP tool layer over HTTP

## 背景

AI クライアント以外（スクリプト、ノーコードツール、他の SaaS）からも盤面を読み書きしたい（ELE_PLT-006）。MCP（ADR 0026）は JSON-RPC なので、curl や Zapier・n8n の HTTP ステップからは扱いにくい。認証は個人用アクセストークン（ADR 0032）がすでにある。

## 選択肢

- 入口：PostgREST に PAT で直接入れる（ゲートウェイで JWT に交換）／Edge Function に REST の経路を置き、MCP と同じツールを呼ぶ
- 何を出すか：テーブルをそのまま／MCP と同じ許可リストのツール
- 失敗の返し方：常に 200 で本文にエラー（MCP と同じ）／HTTP ステータス

## 決定

- **Edge Function `alcon-api` に REST の経路を置く。** 経路 1 本がツール 1 個に対応し、処理は `_shared/boardTools.ts` / `strategyTools.ts` をそのまま呼ぶ。別実装は作らない。
- **許可リストは MCP と同じ 1 本。** `_shared/externalTools.ts` の `EXTERNAL_READ_TOOLS` / `EXTERNAL_WRITE_TOOLS` を alcon-mcp と alcon-api の両方が読む。許可リストのツールはどれもちょうど 1 本の経路を持ち、それ以外のツールには経路がない。削除・一括変更・Object 間の移動・Object の編集は出さない。これをテストで固定する。
- **経路の入力はツールの入力スキーマで検査する。** GET はクエリ文字列、POST / PATCH / PUT は JSON の本文。未知のフィールド・必須の欠落・型と列挙の不一致は 422。パスの `{id}` はツールの引数（`id` か `elementId`）に入り、本文で同じ引数を渡すと 422。OpenAPI（`GET /openapi.json`）も経路表とスキーマから組み立てるので、文書と実装がずれない。
- **失敗は HTTP ステータスで返す。** 400（本文が JSON でない）、401（トークンがない・無効）、403（読み取り専用のトークンでの書き込み、RLS が拒んだ書き込み。見えない Object への作成も含む）、404（経路がない、または本人に見えない）、405、422（入力が不正、または盤面が受け付けない）。本文は `{ "error": { "code", "message" } }`。見えない Element は 403 ではなく 404 にし、境界の外に何があるかを漏らさない。
- **名義は「API · token: <名前>」。** `X-Alcon-Client` ヘッダーで名乗れば「n8n (API · token: ops)」になる。MCP と同じく名前に使える文字だけに絞る。
- **読み取り専用のトークンは書き込みの経路で 403。** ツールを呼ぶ前に断り、`runExternalTool` も同じ許可リストでもう一度断る。

## 根拠

PostgREST に直接入れると、出すテーブルと操作を RLS だけで絞ることになり、削除や一括更新まで外に開く。MCP で「外部からはしない」と決めた操作（ADR 0026）を、REST だけが行えるようになる。同じツールを呼べば、可視性の確認・Activity の記録・担当の境界（ADR 0028）が MCP と同一になり、ツールを直せば両方が直る。

MCP はツールの失敗を本文で返す（モデルが読んで回復するため）。REST の呼び出し側はプログラムなので、ステータスで分岐できる方が扱いやすい。

## 覆す条件

- 一覧で 200 件を超えて読みたいという要求が出たら、ツールにページングを足し、経路にカーソルを出す
- 削除や一括変更を外部から行いたいという要求が出たら、MCP と同時に決め直す（REST だけに足さない）
- Webhook（盤面の変化を外へ通知する）が要るようになったら、別の ADR で扱う
