# 0041 — ボードの在席は、対象を見られる人だけが入れる非公開チャンネルで伝える

## 背景

ボードは対象（Object / Domain / Initiative / Element）を見られる全員の共有の掲示板になった（[0039](0039-widgets-are-shared-components-with-an-origin-and-boards-are-placements.md)）。ところが画面には、ほかに誰がそのボードを開いているかが出ず、個人のダッシュボードと見分けがつかない。

在席は保存するデータではなく、いま開いている人の一覧である。Supabase Realtime の presence で配れる。ただし公開チャンネルは、トピック名を知っている認証済みの人なら誰でも入れて、在席者の名前を受け取れる。

## 選択肢

1. **公開チャンネル** — トピックに対象の UUID を使い、推測されにくさに頼る。
2. **非公開チャンネル** — `realtime.messages` の RLS で、入れる人を決める。
3. **在席をテーブルに書く** — 開いている人の行を書き、RLS で読ませる。

## 決定

2。トピックは `board:<kind>:<id>`（Home の個人ボードは在席を出さない）。`board_presence_allowed(topic)` がトピックを解析し、既存の `user_can_see_widget_subject` で判定する。`realtime.messages` の presence に対して、受け取り（select）と名乗り（insert）の両方にこの判定を掛ける。

名乗る名前は本人の human Worker の名前（なければプロフィールの表示名）。担当者として既にほかのメンバーに見えている名前で、新しい情報を出さない。受け取った名前は表示の文字列にだけ使う。

画面は、ボードの「+」の横に、自分以外の在席者のアバターを出す。ひとりのときは何も出さない。

## 根拠

**公開チャンネルにしない理由。** UUID は URL やログ、Copilot の出力に現れる。対象を見られない人が、誰がそれを見ているかを知れてしまう。可視性はこれまで全部 RLS で決めてきたので、在席だけを例外にしない。

**テーブルにしない理由。** 在席は秒単位で変わり、タブを閉じれば消えるべきもの。行で持つと、消し忘れの掃除と書き込みの量が問題になる。presence は切断で自然に消える。

## 覆す条件

- 「誰がいつ何を変えたか」の履歴が要る — 在席とは別に、変更の記録として行で持つ。
- ボードの面ごと（Overview と Summary）に在席を分けたい — トピックに面を加える。
- 非公開チャンネルの判定が接続のたびに重く、ボードを開くのが遅くなる — 判定の結果をキャッシュするか、トピックを Space 単位に粗くする。
