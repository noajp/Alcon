# 0042 — Slides は Kata の編集画面を Space の資料の上で動かす

## 背景

議事録や文章を、論点・語る順番・ページの型・世界観の通ったスライドに組む別アプリ Kata（`~/Dev/kata`、Next.js、約 1 万行）を作った。資料は localStorage に置き、AI は Next の API ルートから Claude を呼んでデッキの JSON だけを返させ、描画は型ごとの部品と世界観トークンが担う。

これを Alcon に取り込み、Sustainment の道具として使い、ボードにも資料を置けるようにする。ボードのウィジェットを全画面にすると、同じ編集画面になること。

## 選択肢

置き場所:

1. App とウィジェット — Sustainment に Slides App、ボードに Deck ウィジェット。全画面で同じ編集画面。
2. ウィジェットだけ — 枠の中で作って直す。
3. 別アプリのまま埋め込む — 別に公開し、iframe かリンクで見せる。

コード:

- a. Alcon に移して一本化する。
- b. Kata を別に育て、部品として取り込む。

## 決定

1 と a。

- **コード**: Kata の `model` / `theme` / `export` / `components` / `store` と `i18n` を `web/src/ActivitySpace/sustainment/slides/kata/` に移した。Kata のテスト（純粋ロジック 150 件余り）も `web/tests/slides/` に移した。
- **保存**: 資料（`decks`）とフォルダ（`deck_folders`）は Space の行で、Space のメンバーが読み書きする。資料は所属 Space から動かず、フォルダと資料は同じ Space に属する。編集画面のストアはそのまま使い、`slides/sync.ts` が行の読み込み、変わったものの書き戻し（600ms まとめ）、ほかの人の変更の取り込み（Realtime）を受け持つ。表示言語・パネルの開閉・マイ・スキル・自分の世界観は本人のもので、ブラウザに残す。
- **AI**: Kata の API ルートを Edge Function `slides-chat` に移した。Claude（`claude-opus-5-5`、構造化出力、拒否時のサーバー側フォールバック）にデッキの JSON だけを返させ、ページへの変換は画面側の部品が行う。関数が使えないときは手元のプランナーが組む。
- **画面**: Slides は Sustainment の App で、編集画面が自分の資料一覧を持つので Alcon のサイドバーを出さない。色は Kata の名前（`--k-*`）を Alcon のトークンに対応させ、Alcon の外観と明暗に従う。スライドの中は資料の世界観トークンで描く。⌘K は Alcon の検索のまま。
- **ウィジェット**: `deck` は資料を参照し（`params.deckId`）、ページを1枚ずつ表示する。「Open full screen」で App と同じ編集画面をその資料で開く。資料は Space のもので、ウィジェットはどれを映すかだけを持つ。

## 根拠

**App とウィジェットにする理由。** 編集画面は3ペイン（資料一覧・ページ・チャット/デザイン/論理構成）で、ボードの枠の幅では成り立たない。一方で資料は Initiative や Object の文脈で見せたい。両方を満たすのは、資料を Space の行にして、App とウィジェットが同じ行を開く形。全画面は App と同じ部品なので、作りは一つで済む。

**別アプリのまま埋め込まない理由。** ログイン・権限・データが Alcon と分かれ、資料を RLS で守れず、ボードから同じ資料を参照できない。

**一本化する理由。** Kata を別に育てると、移植した部品との同期が続く。編集の規約と赤入れは Kata の資産だが、Alcon の中で育てれば、資料を盤面のデータ（Element・Initiative・Note）から組む次の段階にそのまま進める。

**資料を Space 単位にする理由。** CRM の記録と同じく、組織の資料として Space のメンバーで共有する。Object や Initiative に紐付けるのはウィジェットの置き場で表す。Domain や Object ごとに見せる範囲を絞る要求が出たら、資料に Domain を持たせる。

**同時編集を資料単位の上書きにする理由。** 資料は1人が組み、ほかの人は読むかページ単位で直すことが多い。ページ単位の合流は、デッキの JSON の構造（ページ・置きもの・書式）に沿った合流規則が要り、移植と同時にやると壊れやすい。今は、手元に未保存の編集がある資料はほかの人の変更で上書きしない、までにする。

## 覆す条件

- 同じ資料を同時に直して変更が消える報告が出る — ページ単位で合流するか、資料に操作ログ（[0040](0040-widget-contents-are-shared-documents-merged-by-key.md) の覆す条件と同じもの）を持たせる。
- 資料をゲストや Domain 単位で見せたい — `decks` に Domain を持たせ、可視性をその Domain に従わせる。
- AI の呼び出しの費用が問題になる — 既定を手元のプランナーにし、Claude は明示の操作で呼ぶ。
- マイ・スキルや自分の世界観を Space で共有したい — それぞれを Space の行に移す。
