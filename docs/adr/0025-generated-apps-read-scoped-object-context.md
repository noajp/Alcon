# 0025 — Generated apps read scoped Object context

> 置き換え: アプリと入力は [0040](0040-widget-contents-are-shared-documents-merged-by-key.md) で共有になった。読み取りは見る人ごとに接続を承認する。読める範囲と読み取り専用の契約はそのまま。

## 背景

保存したフォームや計算機を案件の実態に結び付け、転記せずにStrategyとExecutionを確認できるようにする。

## 選択肢

- 生成時に実データをコードへ埋め込む。
- iframeにデータベースクライアントや任意検索を渡す。
- 配置先に限定した読み取り契約を親から提供する。

## 決定

`AppSource.usesObjectData` が有効なアプリに `await alcon.readContext()` を提供する。接続範囲はプレビューと保存版の上に表示する。既存アプリは既定で無効。引数でObjectやユーザーを切り替えることはできず、親が配置先Objectと現在のユーザーを固定する。iframeの送信元とchannelを確認し、同時取得と連続取得を制限する。

hooks内で本人のSupabaseクライアントとRLSにより、Object、primaryとmulti-homeのElements、関連InitiativesとIntent、Domain、Phaseを読む。置き換え済みの判断と未測定の指標を区別できる値を返す。読み取りの前後で本人とObjectアクセスを確認する。ページングで件数を検証し、失敗や上限超過は部分集計にせずエラーにする。

これは取得日時付きの複数クエリの観測であり、原子的スナップショットやリアルタイム購読ではない。共通サマリーは初回と更新ボタンで取得し、失敗時は古い集計を取り除く。生成指示も同じ振る舞いを要求する。アプリ入力とは分離し、取得した記録を生成コードへ埋め込まない。実データを生成モデルへ送ることもない。

ElementやStrategyへの書き込み、外部通信、Table取得はこの契約に含めない。APIキー・任意SQL・認証情報はiframeへ渡さない。

## 根拠

作成・版管理・個人入力の仕組みを維持したまま、案件の目的と実行を自作アプリで読める。本人が読めない情報や他案件を新たに公開せず、データ更新と取得失敗を現物で検証できる。

## 覆す条件

更新頻度が手動再取得では足りない実需要が確認されたら、失効処理を含む購読契約を設計する。外部リサーチやTable接続、業務データへの反映を実装する際は、出典・権限・操作ごとの能力契約を追加する。任意のネットワークやSQLをこのAPIへ広げない。
