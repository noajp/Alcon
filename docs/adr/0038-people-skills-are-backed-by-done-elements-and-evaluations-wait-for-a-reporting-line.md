# 0038 — People のスキルは完了済み Element を根拠に持ち、評価はレポートラインを待つ

## 背景

Team は Worker の所属・担当・通常稼働時間を並べる名簿だった。「次の仕事を誰に渡すか」「誰が何を知っているか」は、人が名簿と過去の Element を頭の中で突き合わせて答えていた。一般的なタレントマネジメントは、スキルもアサイン履歴も自己申告で入力させる。盤面には、誰がどの Object のどの Element を担当し、完了させたかがすでにある。

人事評価も同じ画面に置きたくなる。しかし評価は CRM と比べて桁違いに機微で、「本人・上長・人事だけが見られる」という上下関係（レポートライン）が要る。Space / Domain のメンバーシップではこれを表せず、Domain の owner が上長とは限らない。

## 選択肢

- アサイン履歴：入力させる／`element_assignees` から導出する
- スキルの根拠：自由記述／本人の完了済み Element を指す
- スキルの範囲：Space ごとに持つ／Worker に持たせる（人の Worker はアカウントに 1 つ）
- 評価：同じ表・同じ境界で持つ／レポートラインと閲覧境界を決めてから別に持つ

## 決定

- **Team を People に育てる。** 別アプリを作ると「人」の画面が Team / Workload / People の 3 つに割れる。view の id は `team` のまま、表示名を People にする。
- **アサイン履歴は導出する。** 名簿が読む `element_assignees` と Element から、Object ごとの担当件数・完了件数・未完了件数・期間（開始または作成日〜期限または最終更新日）を純粋関数 `assignmentHistory` で出す。入力欄は作らない。
- **スキルは Worker に持たせ、根拠は本人の完了済み Element にする。** `worker_skills`（名前・レベル 1 Learning〜4 Expert）と `worker_skill_evidence`（skill × element）。根拠に追加できるのは、そのスキルの Worker に割り当てられた `done` の Element だけで、RLS の insert 条件で強制する。人も AI エージェントも同じ表で扱う。
- **境界は既存の規則に乗せる。** スキルは Worker が見える人に見える（`worker_availability` と同じ）。根拠の行は、その Element を見られる人にだけ見える。書き込みは `alcon_internal.user_can_manage_worker`（Worker の編集と同じ、ADR 0028）。
- **スキルの索引で「誰が何を知っているか」に答える。** `skillIndex` が名簿内のスキルを表記ゆれ（大文字小文字・空白）をまとめて集計し、保持者をレベル → 根拠の件数の順に並べる。People の画面ではこれをスキルの絞り込みに使う。
- **評価は People に入れない。** レポートラインと閲覧権限の設計を別の ADR で決め、評価は RLS の境界ごと別の表に置く。

## 根拠

導出したアサイン履歴は入力の手間が無く、盤面とずれない。スキルの根拠を Element に紐づけると、「React: Proficient」という申告を、それを示す完了済みの仕事で確かめられる。これは「意図で委ね、成果と根拠で確かめる」をそのまま人に当てはめたもの。根拠を本人の完了済み Element に限るのは、他人の仕事や未完了の仕事を根拠にすると、確かめる材料にならないため。

評価コメントが Space のメンバーに漏れる事故は、一度起きると信頼を取り戻せない。スキルと同じ境界に評価を置くと、後から境界を狭めることになり、その間は漏れている。

## 覆す条件

- **Workload の平準化でスキルを考慮したくなった**（ADR 0037 の覆す条件）→ `bestTarget` の点数に、渡す Element の Object で根拠を持つスキルの保持者を加点する。
- **スキル名の表記ゆれが索引で吸収できない**（同義語・言語違い）→ Space ごとのスキル辞書（正規名と別名）を持つ。
- **レポートラインが決まった** → 評価の表を別の閲覧境界で作り、People に評価のタブを足す。スキルとアサインの境界は変えない。
- **スキルが Space を越えて見えることが問題になった**（人の Worker はアカウントに 1 つなので、スキルは所属するすべての Space に見える）→ `worker_skills` に `activity_space_id` を足して Space ごとに持つ。
