# 0024 — Generated apps live in Object widgets

## 背景

Object Overview内で必要な小さなアプリをAIで作成し、再訪してもアプリと入力を保持する。配置ごとのコードと業務入力を同じJSONに入れると、画面の改訂が入力を消す。

## 選択肢

- 固定の表示テンプレートだけを生成する。
- Reactアプリごとにビルドとホスティングを行う。
- 共通ランタイムでHTML/CSS/JavaScriptを動かし、配置とは別に保存する。

## 決定

初版は共通ランタイムを使う。`widget_apps` は所有者・Object・配置IDに結び付き、保存版、プレビュー、直前版、作成依頼を保持する。`widget_app_data` はそのアプリのJSON入力を独立して保持する。両者の更新はrevisionによる比較更新とする。

生成は認証済みEdge Functionを通し、呼出者のRLSで確認したアプリだけを編集対象にする。生成結果はプレビューとして保存し、利用者の「Use this app」で採用する。プレビュー操作は本番データを書かない。版を戻す際にも入力を保持する。

画面はopaque originのsandbox iframeで動かす。親のframe-src制約で外部へのframe遷移を禁止し、内側のCSPで外部資源・通信を禁止する。認証情報を渡さず、送信元windowとランタイム固有channelを検証したメッセージだけが当該アプリの入力を保存できる。APIキー、任意SQL、Table/Elementの読み書き、外部連携は提供しない。

初版は個人の配置と個人の入力。Objectを共有していてもアプリの入力を他人に公開しない。ウィジェットを取り除いてもアプリ記録は削除しないが、同じ配置IDを復元しない限り新しいウィジェットからは再接続されない。

## 根拠

別サービスのデプロイを要求せず、フォーム・計算機・記録画面をOverview内で作れる。ビルド依存を持たないvanilla JavaScriptで最初の利用を検証する。データの競合・通信失敗は利用者に表示し、成功していない入力を保存済みとしない。起動通知は検証の一部であり、業務計算の正しさを保証しない。

## 覆す条件

複数人で同じ入力を扱う実需要が確認されたら、配置と共有アプリ定義を分け、明示的な共有権限を追加する。UI規模がvanilla JavaScriptで維持できない場合は、同じ保存・権限契約のままReactのビルドランタイムへ移す。Table/Element操作や外部連携はそれぞれサーバー側の能力契約を設計してから追加する。
