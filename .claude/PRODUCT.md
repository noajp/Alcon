# Alcon の考え方

## 何を作っているか

ビジネスの活動に要る仕事を、人と AI が一つの場所で回せる運用基盤。問い合わせへの対応、営業、採用、開発、改善活動のような日々の仕事を全部ここでこなせるようにし、いずれは組織の活動に欠かせないものにする。

## 三つの分類の出どころ

人の活動と組織の活動を、少数の共通概念で扱う。

| Alcon | ハンナ・アーレント『人間の条件』 | 軍事 |
|---|---|---|
| **Strategy** — 何を達成し、どう勝つか | 活動（action）：人々の間で始め、方向を決める | 戦略 |
| **Execution** — 実際に行動する | 仕事（work）：形のあるものを作る | 作戦 |
| **Sustainment** — 活動を続ける | 労働（labor）：繰り返し、活動を保つ | 兵站 |

## 作りの三層

### 操作画面 — Maven Smart System のように

人は流れを見て、判断と評価だけをする。

- 仕事は Element として左から右へ流れる。列は状態（案 → 判断待ち → 実行中 → 評価待ち → 完了）。人にしかできない動詞（判断・決定・承認・回答）の Element は判断待ちに並ぶ
- 列は仕事の種類ごとにハーネスから作り、人が足し引きできる
- 画面は一つの決まった流れに沿う。各自が好きに組むダッシュボードにしない
- 意図（Strategy の目的と成功条件）が画面の中にある。仕事が終わったことと、目的を勝ち取ったことを分けて見せる

### AIP — Muse のように

モデルは部品で、価値はその外側の仕組み（ハーネス）で決まる。設計の手本は Muse（`~/Desktop/Muse関連/Muse ハーネス詳細まとめ.md`）。

- **エンジン**：モデルは差し替え可能。役割（分解・実行・検証・要約）で使い分ける
- **ハーネス**：仕事のやり方の定義。目的・手順・止める条件・点検・成果物の型・使うコネクタ・分け方・担当の決め方を書く。書いた時点で検査し（コンパイラ）、名前と1行の説明で見つけられるようにする（カタログ）
- **コネクタ**：外とのつながり。MCP か HTTP。資格情報は Vault に置き、モデルにも道具の引数にも出さない
- **承認**：AI が書き込む前の承認は、実行する入力そのものに紐づける。権限を超えるものは人の判断待ちに回す
- **トリガー**：時刻・イベント・Webhook・他の仕事の完了で、ハーネスを起動する。機械的な設定で、AI に判断させない

### データ — Supabase

Postgres に意味の層を持つ。名詞（Strategy / Domain / Object / Element / Worker / Property / Table の行）、リンク（含む・依存する・担当する・従う・生む・止める・判断した）、アクション（Element の動詞）を固定し、すべての事実とリンクに出所・誰が・いつを持たせる。汎用のオントロジー基盤は作らない。

## 仕事が回る形

1. **上から**：人が Strategy（意図と成功条件）を書く → Planner がハーネスの分け方で Object と Element に分ける → 人が確かめて作る
2. **下から**：外で起きたこと（メール・フォーム・障害・申請）をトリガーが拾う → ハーネスが分類し、Table に記録し、担当を決めて Element にする
3. AI か人が実行する → 人が判断待ちと評価待ちをさばく → 成功条件と照らし合わせる → 次の Strategy へ

例：Gmail をつなぐと、問い合わせを Table に集計し、分類して担当者の Element にし、クレームを分析して改善の Strategy を提案する。

## 次に作るもの

いまの main で足りないもの。上から順に効く。

| 項目 | 足りないこと |
|---|---|
| トリガー | AI は人が「Run」を押したときしか動かない。時刻・イベントで起動する仕組みがない |
| 流れのボード | Element が状態の列を流れる画面。判断待ちと評価待ちを列として見せる |
| アクションの一覧 | 動詞ごとに、誰ができるか・入力・状態の変化・確かめ方を持つ。`checkHarness` がこれで検査する |
| 担当の決め方 | Planner は「AI か人か」までしか決めない。Space の Worker を渡し、ハーネスの規則で個人に割り当てる |
| Gmail コネクタ | Google の OAuth は Drive の権限だけ。Gmail の読み取りを足す |
| リンクの統一 | 関係が組み合わせごとのテーブルに分かれている。`intent_bindings` を広げて汎用の `links` にする |
| 外部 ID の対応表 | Table の行や外部システムのレコードを Element につなぐ `external_refs` |
| 学習 | 効いたハーネスを残し、効かない変更を引退させる見直し（Muse のスキルレビューにあたる） |
