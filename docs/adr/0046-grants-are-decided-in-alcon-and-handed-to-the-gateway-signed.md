# 0046 — 権限は Alcon で決め、署名した版つきの表としてゲートウェイに渡す

## 背景

AI が顧客の業務を外部の実行基盤（ゲートウェイ）で代行するとき、「どの導入が、どの接続で、何をしてよいか（読む・下書き・送る・お金）」を決める場所と、それを守らせる場所が要る。操作を実際に行うのはゲートウェイなので、止められるのはゲートウェイだけである。一方、決めるのは顧客の Space のオーナーで、決めた内容と、その内容がいつから効いていたかは監査で問われる。AI 自身が権限を広げられる経路があると、権限表は意味を失う。

## 選択肢

1. 権限はゲートウェイの設定に置き、Alcon は表示だけする
2. 権限は Alcon を正本とし、ゲートウェイは操作のたびに Alcon へ問い合わせる
3. 権限は Alcon を正本とし、版つき・期限つきの表に署名してゲートウェイへ配る。ゲートウェイは手元の表で判断し、記録には判断に使った版を残す

## 決定

3 を採る。

- 権限は `deployment_grants`（導入 × 接続 × 操作 の行）に置く。追加と削除だけができ、編集はない。変えられるのは Space のオーナーが本人としてログインしているときだけで、委任された呼び出し（個人アクセストークン・OAuth）からは変えられない。service role からは書き込みの権限を外す。外部のエージェントも、Edge Function で動くエージェントも、権限を広げられない
- 変えるたびに、DB が導入ごとの次の版を `deployment_grant_versions` に追記する（その時点の権限の全体を並べた値）。導入の行をロックしてから番号を振るので、同じ番号が2回出ることはない。版は書き換えも削除もできない
- 配布は Edge Function `audit-grants`。ゲートウェイは記録の受け口（ADR 0045）と同じ鍵で、鍵 id と時刻に署名して要求する（時刻は Alcon の時計から5分以内）。返すのは、その鍵の Space にある全導入の最新版と導入の状態で、Alcon の Ed25519 鍵（関数の秘密 `AUDIT_GRANTS_SIGNING_KEY`）で本文に署名する。ゲートウェイは Alcon の公開鍵を導入時に固定し、表に書かれた鍵は信じない
- 表の期限は15分。期限が切れたら、ゲートウェイは送信とお金の操作を止め、読む・下書きだけを手元の最後の表で続ける。表がない・導入が表にない・導入が停止中なら、何も許さない（`_shared/auditGrants.ts` の `decideOperation` が正本）
- ゲートウェイは各記録に、判断に使った版（`grants_version`）を入れ、記録のダイジェスト（ADR 0045）に含める。権限の外の操作を止めたときも、`blocked` として記録する
- 受け口は記録ごとに、その版に接続と操作が含まれているかを判定し、`workflow_run_steps.outside_grant` に残す。版が存在しない、版に含まれない、または送信・お金で、その版が次の版に置き換わってから15分より後に行われた操作は、権限の外とする。権限の外の操作は、止められたものも行われたものも、実行の結果を「権限外の操作」にする
- 画面は Audit のワークフローに「権限」タブを置き、接続 × 操作の表をオーナーが編集する。版の履歴と、権限の外の操作の件数を同じ場所に出す

## 根拠

- 1 は、決めた人と守らせる場所が分かれず、ゲートウェイの運用者が黙って広げられる。監査で「いつ誰が許したか」を Alcon が示せない
- 2 は、Alcon が落ちるとすべての操作が止まり、操作ごとの往復が遅い。3 は手元の表で判断するので、Alcon が落ちても期限までは動き、期限後も安全な操作だけが続く
- 版を記録に入れ、ダイジェストで封じるので、後から「新しい版では許されていた」と読み替えられない。受け口が版で判定するので、ゲートウェイの判断が正しかったかを Alcon 側で確かめられる
- 期限切れで止めるのを送信とお金に限るのは、読む・下書きは外へ出ず、人が後で確かめられるため

## 覆す条件

- 15分の配布遅れが業務上許されない場合（権限を外した直後に止める必要がある）→ 権限を外したときに、ゲートウェイへ表の取り直しを促す通知の経路を足す
- 受け口の判定（版の作成時刻とゲートウェイの時刻の比較）が、時計のずれで誤った逸脱を出す場合 → 判定に時計のずれの許容を足すか、版の置き換えの判定を受け取った時刻で行う
- 1つのゲートウェイが複数の Space の導入を扱う必要が出た場合 → 鍵を Space をまたいで登録できるようにし、表を Space ごとに分けて署名する
- Alcon の署名鍵を替える必要が出た場合 → 新旧の公開鍵を並べて配り、ゲートウェイがどちらでも検証できる期間を置いてから古い鍵を外す
