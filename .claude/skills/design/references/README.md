# Friction UI 基準資料体 — references/

Friction の UI 実装で「Linear ならどうするか」を判断するための、**出典つきの一次調査記録**。

各エージェントが記憶から基準を再導出すると、判断が毎回ぶれる。この資料体はその再導出を不要にするために存在する。ここに書いてある px 値・キー名・フォーカスの行き先は、実際に調べた結果であって、思い出した内容ではない。

## DESIGN.md との関係 — 三者の分担

3 つの層が別々のものを持つ。役割が違うので競合しない。

| 層 | 持つもの |
| :--- | :--- |
| `web/src/app/globals.css` / `designTokens.ts` | **色・寸法・モーションの実値。** 唯一の正 |
| `../DESIGN.md` | **規則と使いどころ。** どのトークンをいつ使うか、なぜそうするか。実数は 1 つも書かない |
| この `references/` | **外部の実測値と、そこから導いた収斂案の実数。** 出典つき |

DESIGN.md が実数を持たないのは意図的な設計だ。実数を転記すると同じ事実に 2 つの居場所ができ、片方だけが更新されて文書が「もっともらしく間違っている」状態になる。**この資料体も同じ規律で扱う** — ここに書く px は「Linear ではこうだった」という**参照点**であり、Alcon の値ではない。Alcon の値になった瞬間に、それはコード側へ移る。

この調査で DESIGN.md の次の 2 つが**実測に裏打ちされた**：
- §5.3「input / textarea / contenteditable に focus ring・枠・アウトラインを付けない」— Linear のコンポーザ入力欄もメニュー検索欄も `outline: none` / `box-shadow: none` / 地色透明で実測一致
- §0.2-2「Borders & Luminance over Shadows」— Linear のメニューは群の区切りに罫線を 1 本も使わず 12px の余白だけで切っている

## 更新の作法

この資料体は追記で育てる。以下は例外なく守る。

### 1. 出典を必ず書く

すべての記述に、[creation-flows.md の凡例](./creation-flows.md#出典の凡例)の 4 ラベルのいずれかを付ける。

| ラベル | 使う条件 |
| :--- | :--- |
| 【実測】 | 自分でブラウザを開き、DOM / スクリーンショットから採取した。**採取日・URL・viewport を書く** |
| 【文書】 | 公開ドキュメントの記述。**URL を書く** |
| 【推測】 | 観測からの推論。断定形で書かない |
| 【未検証】 | 記憶から書いた。裏取りしていない |

**ラベルの無い記述を追加しない。** 出典が書けないなら、それは調査ではなく思い出しなので、調べてから書く。

### 2. 未検証は隠さず、末尾にまとめる

各ファイルの末尾に「未検証・積み残し」節がある。調べられなかったことは**そこに書き残す**。何が分かっていないかが分かる状態を保つのが、この資料体の価値の半分。次の調査者はそこから始める。

分からないことを推測で埋めて断定形で書くのが、この資料体を最も早く壊す。

### 3. Friction への適用まで書く

「Linear はこうしている」で終わった記述は、実装エージェントには使えない。各パターンに必ず次の 2 つを書く。

- **Friction の現状との差分** — 該当ファイルと**行番号**を挙げる。パスはリポジトリ相対（`web/src/...`）で書く。worktree の絶対パスは消えるので使わない
- **Friction にどう適用するか** — px・ms・キー名・フォーカスの行き先まで書く。「揃えるべき」ではなく「`208px` にする」と書く

### 4. 抽象論を書かない

「一貫性が重要」「ユーザー体験を向上させる」の類は 1 行も要らない。実装できる粒度だけを書く。

### 5. 調査は実際にブラウザで行う

`preview_start` に `{url: "..."}` を渡せば外部サイトを開ける。DOM の `getBoundingClientRect()` / `getComputedStyle()` で採寸すると、スクリーンショットの目視より正確で、px 値をそのまま資料に書ける。

**制約**：ログインしない。資格情報を入力しない。有料 / 非公開領域に入らない。相手の画像やコードを複製しない。**自分の言葉でパターンを記述する**。書くのは「何を学んだか」であって「何をコピーしたか」ではない。

権限等でブラウズできなければ諦めてよい。その場合は【未検証】と明記して自分の知識から書く。嘘をつかず、後で検証可能な形にしておく。

### 6. 行番号は腐る

Friction 側のコードは動くので、参照した行番号はいずれずれる。**行番号だけでなく、識別できる引用（関数名・変数名・短いコード片）も併記する**。行がずれても再発見できるようにしておく。
